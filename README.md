# K-pop 뉴스 자동 발행 파이프라인 (워드프레스용)

넓은 키워드 조합으로 최신 K-pop 뉴스를 모아 Gemini로 재작성하고, 사진 대신
**타이포그래피 그래픽 카드**를 자동 생성해 워드프레스에 발행합니다.

기존 Blogger 자동화 스크립트에서 검증된 로직(넓은 키워드 검색,
제목 유사도 기반 중복 방지)을 그대로 이식했습니다.

## 1. 사전 준비

### 1) 워드프레스 Application Password 발급
1. `워드프레스 관리자 → 사용자 → 프로필` 이동
2. 맨 아래 "Application Passwords" 섹션에서 이름(예: `auto-publish`) 입력 후 발급
3. 발급된 비밀번호(공백 포함 16자리)를 `config.py`의 `WP_APP_PASSWORD`에 붙여넣기

### 2) Gemini API 키 발급
https://aistudio.google.com/apikey 에서 발급 → `GEMINI_API_KEY`에 입력

이 스크립트는 **`google-genai` 공식 SDK**로 인증합니다. raw REST 호출로 직접
`?key=` 파라미터를 붙이는 방식이 아니라서, 계정에 따라 다른 형식(`AIzaSy...`,
`AQ.Ab8...` 등)으로 발급되는 키도 SDK가 알아서 처리해줍니다.

### 3) 이미지 처리 방식 — 사진 없는 타이포그래피 카드
연예인 사진을 다운로드하거나 AI로 변환하는 과정을 전부 없앴습니다. 대신
카테고리 이름 + Gemini가 함께 생성하는 짧은 문구(`card_label`, 2~5단어)만으로
사이트 톤(딥인디고 배경 + 네온핑크/라임 액센트)에 맞는 그래픽 카드를
`Pillow`로 직접 그려서 대표이미지로 씁니다.

- **저작권/초상권 리스크 없음**: 실제 인물 사진을 전혀 사용하지 않습니다.
- **외부 API 비용 없음**: 이미지 생성이 로컬에서 즉시 처리됩니다 (Gemini 이미지
  모델의 유료 할당량 문제와 무관).
- 카드에 쓰이는 글꼴(Anton, OFL 라이선스로 자유 재배포 가능)은 최초 실행 시
  자동으로 다운로드되어 `Anton-Regular.ttf`로 로컬에 캐싱됩니다. 이후 실행부터는
  다시 받지 않습니다.
- 카드 디자인을 바꾸고 싶으면 `auto_publish.py`의 `generate_typography_card()`
  함수에서 배경색, 액센트 색, 폰트 크기 등을 조절하면 됩니다.


## 2. 설치

```bash
pip install -r requirements.txt
cp config.example.py config.py
# config.py를 열어 위에서 발급받은 값들을 채워넣으세요
```

## 3. 테스트 실행

먼저 `config.py`에서 `POST_STATUS = "draft"`로 바꿔서 임시저장으로 테스트하는 걸 추천합니다.

```bash
python auto_publish.py
```

## 4. 콘텐츠 언어

`config.py`의 `CONTENT_LANGUAGE`로 재작성 언어를 정합니다.
- `"en"` (기본값): 기존 Blogger 자동화와 동일하게 영어로 번역/재작성 — 글로벌 K-pop 팬 타겟
- `"ko"`: 한국어 그대로 재작성

**주의**: 언어를 바꾸면 AI가 반환하는 카테고리 이름(Comeback/컴백 등)도 같이
바뀝니다. 이미 반대 언어로 생성된 카테고리가 워드프레스에 남아있으면 두 세트가
공존하게 되니, 언어를 바꾼 뒤에는 워드프레스 관리자 → 글 → 카테고리에서 기존
카테고리를 새 언어 이름으로 통일하거나 병합해주세요.

## 4-1. 짧은 SEO 슬러그 (고유주소)

Gemini가 기사 제목과 함께 3~6단어짜리 짧은 영문 슬러그도 함께 생성해서, 워드프레스
글 주소가 제목 전체가 아니라 `/ive-liz-red-carpet-comeback/`처럼 짧고 핵심적으로
나오도록 되어 있습니다. AI가 슬러그를 안 주는 경우엔 제목 앞 6단어로 자동
대체합니다.

이 기능이 실제로 주소에 반영되려면, 워드프레스 관리자 → **설정 → 고유주소
(Permalinks)** 에서 **"글 이름(Post name)"** 옵션을 선택해야 합니다. ("기본
(Plain)"으로 되어 있으면 슬러그를 지정해도 여전히 `?p=123` 형식으로 나옵니다.)

## 5. 검색 범위 조정

`config.py`의 `BASE_ARTIST_KEYWORDS`(아이돌 그룹명만 사용)로 구글 뉴스를
검색합니다. 실행할수록 최근 기사를 다 써버려서 "새 기사가 안 나오는"
문제가 생길 수 있으니, 그룹 목록을 넓게 유지하는 걸 추천합니다. `RECENCY_DAYS`로
검색 범위(최근 며칠)도 조절 가능합니다.

## 6. 자동 실행 설정 (Windows)

두 가지 방식 중 편한 걸 고르세요.

### 방식 A: 더블클릭 후 창을 계속 켜두기 (가장 간단)
`config.py`에서 `RUN_CONTINUOUSLY = True`로 설정한 뒤, `run.bat`을 더블클릭하세요.
스크립트가 알아서 한 번 실행 → `MIN_INTERVAL_MINUTES`~`MAX_INTERVAL_MINUTES` 사이
무작위 시간만큼 대기 → 다시 실행을 무한 반복합니다. 이 창을 닫으면 멈춥니다.
컴퓨터를 켜둔 상태로 계속 두는 방식에 적합합니다.

### 방식 B: Windows 작업 스케줄러로 예약 실행 (창 없이 백그라운드)
컴퓨터가 켜져 있을 때만 특정 시간마다 조용히 실행하고 싶다면:
1. `config.py`에서 `RUN_CONTINUOUSLY = False`로 설정 (스케줄러가 대신 반복을 담당하므로)
2. 시작 메뉴에서 "작업 스케줄러" 검색 후 실행
3. 오른쪽 **"기본 작업 만들기"** 클릭 → 이름 입력(예: K팝뉴스 자동발행)
4. 트리거: **"매일"** 선택 후 반복 간격은 고급 설정에서 "작업 반복 간격"을 2~3시간으로 지정
5. 동작: **"프로그램 시작"** → 찾아보기에서 `run_scheduled.bat` 선택
6. 완료 후 실행 결과는 같은 폴더의 `run_log.txt`에서 확인 가능

### 컴퓨터 부팅 시 자동 시작하고 싶다면
`run.bat`의 바로가기를 만들어서 다음 폴더에 넣으면, 로그인할 때마다 자동으로 실행됩니다:
`Win + R` → `shell:startup` 입력 → 열린 폴더에 `run.bat` 바로가기 복사

## 7. 운영 팁

- `MAX_POSTS_PER_RUN`과 `SPREAD_MINUTES`로 실행당 발행 개수와 발행 간격을 조절해서
  스팸처럼 보이지 않게 관리하세요.
- `SIMILARITY_THRESHOLD`를 더 낮추면(예: 0.2) 훨씬 더 엄격하게 중복을 걸러냅니다.
  반대로 값을 높이면(예: 0.6) 아주 비슷한 제목만 중복으로 판정해서 더 관대해집니다.
  기본값 0.3은 "조금만 비슷해도 걸러내는" 쪽에 맞춰져 있습니다.
- `posted_links.json`, `posted_titles.json`은 자동 생성되는 중복 방지 캐시입니다.
- 직캠/컴필레이션 영상(`[K-Fancam]`, `Facecam` 등)과 유튜브 링크는 기사 본문이 없어서
  자동으로 건너뜁니다.
- Gemini 재작성 응답에 `card_label`이 비어있으면 제목 전체를 그대로 카드에
  사용합니다. 카드 문구가 너무 길면 자동으로 최대 4줄까지 줄바꿈됩니다.
- SEO 메타 설명(`_yoast_wpseo_metadesc`)이 Gemini 재작성 단계에서 자동으로
  채워집니다. 워드프레스 테마에서 이 필드를 REST API로 받도록 등록해뒀으니,
  Yoast SEO 플러그인이 설치되어 있어야 검색결과에 반영됩니다.
- Gemini 무료 등급 일일 요청 한도가 모델마다 크게 다르고, **모델 세대교체와
  지원 종료가 굉장히 자주 일어납니다**. `GEMINI_MODEL`에 설정해둔 모델이
  "no longer available" 같은 404 오류를 내면, 그 에러 메시지가 직접 안내하는
  최신 모델명으로 바로 교체하는 게 가장 확실합니다 (블로그 글이나 검색결과의
  구체적인 수치보다 실제 에러 메시지가 더 최신 정보입니다).
- 순간적으로 429(할당량 초과) 오류가 나면, 에러가 알려주는 대기시간만큼
  자동으로 기다렸다가 재시도합니다 (`call_gemini_with_retry`, 최대 4회).
  다만 이건 일시적인 버스트 제한에만 도움이 되고, 하루 총량 자체를 다 써버린
  경우엔 다음날까지 기다리거나 모델을 바꿔야 합니다.
- 제목에 그룹명(`GROUP_ALIASES`)이나 일반적인 K-pop 용어(`GENERIC_KPOP_TERMS`)가
  전혀 없는 기사는 아예 처리하지 않고 건너뜁니다. 구글 뉴스 검색이 가끔
  키워드와 무관한 기사(정치, 사회 뉴스 등)를 섞어서 반환하는 경우가 있어서,
  이런 오탐지를 걸러내기 위한 안전장치입니다.
- 매 글마다 `ANGLE_STYLES`(팬 반응/업계 분석/커리어 타임라인/비교/Q&A/비하인드/
  데이터 관점) 중 하나와 `STRUCTURE_STYLES`(불릿리스트/표/인용구 등) 중 하나를
  무작위로 골라 강제 적용합니다. 같은 소식이라도 매번 다른 각도·구성으로
  써져서, 여러 글을 몰아봤을 때 톤이 반복되는 느낌을 줄여줍니다.
- `run_scheduled.bat`은 `run_log.txt`가 5MB를 넘으면 자동으로
  `run_log_old.txt`로 백업하고 새로 시작합니다. 로그가 무한정 커지는 걸 막아줍니다.

## 8. 테마 연동

같이 제공된 `kpop-news-theme` 워드프레스 테마는 이 스크립트가 채우는
`source_url`, `source_name` 메타값과 대표이미지(featured image)를 자동으로
기사 하단 출처 표기 및 카드 썸네일로 사용하도록 만들어져 있습니다.

## 9. 기존 Blogger 글 이관하기 (migrate_from_blogger.py)

`kpop2027.blogspot.com`처럼 기존에 운영하던 공개 Blogger 블로그의 글 전체를
워드프레스로 옮기는 별도 스크립트입니다. 로그인/OAuth 없이 Blogger의 공개
피드만으로 동작합니다.

**하는 일**
- 전체 글을 발행일 오래된 순으로 수집
- **본문 속 원본 사진은 전부 제거**하고, `auto_publish.py`와 동일하게
  그룹 사전 제작 이미지(있는 경우) 또는 타이포그래피 그래픽 카드로 대표이미지를
  자동 생성합니다 (저작권/초상권 리스크 없음)
- Blogger 라벨을 워드프레스 카테고리로 매핑
- 원래 발행일(`date_gmt`)을 그대로 유지
- 이미 이관한 글은 `migrated_posts.json`에 기록해서 재실행 시 건너뜀
- `MIGRATE_SINCE_DATE`/`MIGRATE_UNTIL_DATE`로 특정 날짜(범위)만 골라서 이관 가능

**사용법**
1. `config.py`에서 `BLOGGER_BLOG_URL`을 이관할 블로그 주소로 설정
2. 처음엔 `IMPORT_POST_STATUS = "draft"`로 두고 실행해서 결과물을 워드프레스
   관리자에서 먼저 확인하는 걸 추천합니다
3. 실행:
   ```bash
   python migrate_from_blogger.py
   ```
4. 결과가 만족스러우면 `IMPORT_POST_STATUS = "publish"`로 바꾸고
   `migrated_posts.json`을 삭제한 뒤 다시 실행하면 이번엔 실제 발행됩니다
   (또는 draft 상태 글들을 워드프레스 관리자에서 일괄 선택 후 "발행"으로 바꿔도 됩니다)

**주의**
- 글이 많으면 `MAX_IMPORT_POSTS_PER_RUN`만큼만 처리하고 멈춥니다. 다시 실행하면
  이어서 다음 글부터 처리됩니다.
- 이관이 다 끝난 뒤, 검색엔진 순위 유지를 위해 기존 Blogger 글에서 새 워드프레스
  글로 301 리다이렉트를 걸어주는 걸 권장합니다 (Blogger는 자체적으로 리다이렉트
  설정 기능이 없어서, 이 부분은 별도로 안내가 필요하면 말씀해주세요).

## 10. 기존 글의 사진 일괄 교체하기 (regenerate_images.py)

이미 사진이 들어간 채로 발행된 글들(자동 발행 글, Blogger 이관 글 모두 포함)의
대표이미지를 전부 타이포그래피 그래픽 카드로 바꿔주는 스크립트입니다.

**하는 일**
- 전체 글(발행글+임시글)을 순회하며 대표이미지를 새로 생성한 그래픽 카드로 교체
- 카드에 들어가는 문구는 각 글의 제목에서 자동으로 뽑아옵니다
- `STRIP_BODY_IMAGES = True`(기본값)면 본문 안에 남아있는 `<img>` 태그도 함께
  제거합니다 — 특히 Blogger 이관 글에 원본 사진이 본문에 그대로 남아있는
  경우를 정리해줍니다
- 이미 처리한 글은 `regenerated_posts.json`에 기록해서, 여러 번 나눠 실행해도
  중복 처리하지 않습니다

**사용법**
```bash
python regenerate_images.py
```
또는 `run_regenerate_images.bat`을 더블클릭

**주의**
- 이 작업은 되돌릴 수 없습니다(기존 대표이미지가 새 카드로 교체됨). 중요한
  사진이 있다면 먼저 백업을 해두세요.
- 글이 많으면 시간이 좀 걸립니다 (`REGENERATE_PAUSE_SECONDS`로 처리 간격 조절
  가능). 중간에 창을 닫아도 다시 실행하면 이어서 처리됩니다.
- 기존에 업로드된 원본 사진 파일 자체는 미디어 라이브러리에서 자동으로
  삭제되지 않습니다 (혹시 다른 곳에서 참조 중일 수 있어 안전하게 그대로 둠).
  용량 정리가 필요하면 워드프레스 관리자 → 미디어에서 수동으로 확인 후
  삭제하시면 됩니다.

## 11. 디스크 용량이 부족할 때

Cafe24 호스팅은 용량 제한이 있어서, 자동 발행이 쌓이다 보면 용량이 꽉 차서
업로드가 실패할 수 있습니다 ("could not be moved" 오류, FTP 전송오류 등).

**가장 효과적인 정리 방법**: `regenerate_images.py` 실행 시 `config.py`에서
```python
DELETE_OLD_FEATURED_MEDIA = True
```
로 설정하면, 대표이미지를 새 그래픽 카드로 교체하면서 **기존 사진 파일을
동시에 완전히 삭제**해서 공간을 바로 확보합니다.

**주의**: 삭제된 이미지는 복구할 수 없습니다. 되돌릴 수 없는 작업이니,
먼저 `DELETE_OLD_FEATURED_MEDIA = False`(기본값)로 한 번 실행해서 결과가
만족스러운지 확인한 뒤, 필요하면 `True`로 바꿔 재실행하는 걸 추천합니다.
(단, 이미 처리된 글은 `regenerated_posts.json`에 기록되어 재실행 시 건너뛰므로,
기존 이미지까지 지우고 싶다면 이 파일을 삭제한 뒤 `True` 설정으로 다시
실행해야 합니다.)

그 외 용량 확보 방법:
- 워드프레스 관리자 → 미디어에서 사용하지 않는 큰 이미지 파일을 수동으로 확인 후 삭제
- `run_log_old.txt`, `run_log.txt` 등 오래된 로그 파일 삭제
- Cafe24 호스팅센터에서 현재 사용 용량과 플랜 한도를 확인하고, 필요하면 플랜 업그레이드

## 12. 고아 미디어 파일 정리하기 (cleanup_orphaned_media.py)

`regenerate_images.py`로 대표이미지를 교체·삭제해도 디스크 용량이 잘 안 줄어드는
경우, 원인은 대부분 **본문 안에 여러 장 들어있던 사진들** 때문입니다.
`regenerate_images.py`는 대표이미지 1장만 처리하는데, Blogger 이관 글은
본문에 사진이 여러 장 들어있는 경우가 많아서, 본문의 `<img>` 태그만 지워도
그 사진 파일(미디어 라이브러리 항목) 자체는 계속 남아있게 됩니다.

이 스크립트는 **전체 미디어 라이브러리를 훑어서, 어떤 글/페이지에도 더 이상
연결되지 않은 "고아 파일"만 찾아 정리**합니다.

**동작 방식**
1. 전체 글/페이지 본문을 스캔해서 실제로 쓰이고 있는 미디어를 식별
   (본문 속 `wp-image-123` 클래스, 파일명 매칭, 대표이미지 지정 여부 기준)
2. 어디에도 해당하지 않는 미디어만 "고아"로 분류
3. 기본값은 **DRY_RUN = True** — 삭제하지 않고 몇 건이 고아인지, 예상 절약
   용량이 얼마인지만 보여줍니다
4. 결과가 예상과 맞으면 `config.py`에서 `DRY_RUN = False`로 바꾸고 다시
   실행해야 실제로 삭제됩니다

**사용법**
```bash
python cleanup_orphaned_media.py
```
또는 `run_cleanup_orphaned_media.bat` 더블클릭

**주의**
- 반드시 **DRY_RUN = True 상태로 먼저 실행**해서 삭제 대상 건수/용량을
  확인하세요. 되돌릴 수 없는 작업입니다.
- 이 스크립트는 글/페이지 본문만 스캔합니다. 혹시 사이트 로고나 커스터마이저에서
  별도로 지정한 이미지가 있다면 그런 것들은 별도 확인이 필요할 수 있습니다
  (일반적인 K-pop 뉴스 자동화 사이트 구조에서는 해당 사항이 거의 없습니다).
- `regenerate_images.py`와 함께 쓰면 좋습니다: 먼저 `regenerate_images.py`로
  대표이미지를 다 정리한 뒤, 이 스크립트로 본문에 남아있던 나머지 고아
  이미지들까지 정리하는 순서를 추천합니다.

## 13. 그룹별 사전 제작 이미지로 디스크 용량 절약 (upload_group_images.py)

매 글마다 새 그래픽 카드 파일을 만드는 대신, **그룹당 직접 만든 이미지 몇 장을
딱 한 번만 업로드해두고 계속 재사용**하는 방식입니다. 게시글이 아무리 늘어나도
이미지 파일 개수는 늘어나지 않아서 디스크 용량 문제를 근본적으로 줄여줍니다.

**중요**: 사용하시는 이미지는 직접 만드신 오리지널 그래픽/일러스트여야 합니다.
실제 인물 사진(공식 화보, 방송 캡처 등)을 그대로 쓰면 저작권/초상권 문제가
다시 생길 수 있습니다.

**사용법**
1. `kpop_auto` 폴더 안에 `group_images` 폴더를 만듭니다.
2. 그 안에 `config.py`의 `GROUP_ALIASES` 키와 **정확히 같은 이름**의 하위
   폴더를 그룹별로 만듭니다 (예: `group_images/BTS/`, `group_images/BLACKPINK/`).
3. 각 폴더에 이미지를 몇 장씩 넣습니다 (1~10장 정도 추천).
4. 실행:
   ```bash
   python upload_group_images.py
   ```
   또는 `run_upload_group_images.bat` 더블클릭
5. 완료되면 `group_images.json`에 그룹별 media ID 목록이 저장됩니다.
   이후 `auto_publish.py`가 자동으로 이 파일을 읽어서, 기사 제목에서
   그룹명을 감지하면 해당 그룹의 이미지 중 하나를 랜덤(또는 순서대로)
   골라 재사용합니다.

**설정**
- `ENABLE_GROUP_IMAGES = True/False` — 이 기능 자체를 켜고 끕니다
- `GROUP_IMAGE_SELECTION = "random"` 또는 `"sequential"` — 무작위로 고를지,
  순서대로 돌아가며 쓸지 선택
- 그룹이 감지되지 않거나 해당 그룹에 이미지가 없으면, 자동으로 기존
  타이포그래피 카드 생성 방식으로 대체됩니다 (안전장치)

**나중에 이미지를 더 추가하고 싶다면**: `group_images` 폴더 안에 새 파일만
추가하고 스크립트를 다시 실행하면, 이미 업로드된 파일은 건너뛰고 새 파일만
업로드합니다.

## 14. 특정 날짜의 글만 이관하기 (migrate_from_blogger.py)

블로그 전체를 매번 다시 훑는 대신, 특정 날짜(또는 날짜 범위)에 발행된 글만
골라서 이관할 수 있습니다.

`config.py`에서:
```python
MIGRATE_SINCE_DATE = "2026-08-31"   # 이 날짜부터
MIGRATE_UNTIL_DATE = "2026-08-31"   # 이 날짜까지 (같은 날짜로 두면 그 하루만)
```

- **특정 하루만**: `MIGRATE_SINCE_DATE`와 `MIGRATE_UNTIL_DATE`를 같은 날짜로 설정
- **그 날짜 이후 전부**: `MIGRATE_SINCE_DATE`만 설정하고 `MIGRATE_UNTIL_DATE`는 `None`으로 유지
- **필터 없이 전체**: 둘 다 `None`으로 유지 (기존 동작과 동일)

기존 블로그 글은 이미 대부분 이관하셨고, **앞으로 블로그에 새 글이 올라올
때마다 그날 날짜만 지정해서 가볍게 돌리는 용도**로 유용합니다.

## 15. 네이버·다음 뉴스도 함께 검색하기

지금까지는 구글 뉴스만 검색했는데, **네이버**와 **다음(카카오)** 뉴스도 함께
검색하도록 확장했습니다. 기본값은 둘 다 꺼져있고(`False`), 원하시는 것만
켜서 사용하시면 됩니다.

### 네이버 뉴스 검색 켜기
1. https://developers.naver.com 접속 → 로그인 → **Application → 애플리케이션 등록**
2. 사용 API에서 **검색** 선택
3. 발급받은 **Client ID / Client Secret**을 `config.py`에 입력:
   ```python
   ENABLE_NAVER_SEARCH = True
   NAVER_CLIENT_ID = "발급받은 클라이언트ID"
   NAVER_CLIENT_SECRET = "발급받은 클라이언트시크릿"
   ```
- 네이버 공식 뉴스 검색 API를 그대로 사용하는 방식이라 안정적입니다.

### 다음(카카오) 뉴스 검색 켜기
1. https://developers.kakao.com 접속 → 로그인 → **내 애플리케이션 → 애플리케이션 추가하기**
2. 앱 생성 후 **REST API 키**를 확인
3. `config.py`에 입력:
   ```python
   ENABLE_DAUM_SEARCH = True
   KAKAO_REST_API_KEY = "발급받은 REST API 키"
   ```
- **참고**: 카카오는 별도의 "뉴스 검색" API를 제공하지 않습니다. 대신 카카오의
  "웹 검색 API" 결과 중 `daum.net` 도메인만 걸러서 사용하는 우회 방식입니다.
  구글/네이버보다 정확도가 다소 떨어질 수 있습니다.

### 동작 방식
`fetch_news_candidates()`가 이제 구글·네이버·다음 세 곳을 모두 조회한 뒤,
링크 기준으로 중복을 제거해서 하나로 합칩니다. 검색 실행 로그에
`📡 Google: N건 추가`, `📡 Naver: N건 추가`, `📡 Daum: N건 추가` 형태로
소스별 결과 건수가 출력됩니다.

## 16. GitHub Actions로 클라우드에서 자동 실행하기

내 PC를 켜두지 않아도, 정해진 시간마다 깃허브 서버에서 자동으로
`auto_publish.py`가 실행되도록 설정할 수 있습니다 (무료 한도 내에서 충분히 가능).

### 준비: config.py를 두 파일로 분리

- **`config_base.py`**: API 키가 없는 일반 설정(그룹 목록, 발행 정책 등).
  이 파일은 깃허브에 올려도 안전합니다.
- **`config.py`**: API 키 등 비밀값만 담고, 맨 위에서
  `from config_base import *`로 나머지 설정을 가져옵니다. 이 파일은
  **`.gitignore`에 포함되어 있어 깃허브에 올라가지 않습니다.**

### 설정 순서

1. **깃허브 저장소 만들기**
   - github.com에서 새 저장소를 만듭니다 (Private 추천 — 코드 자체엔 비밀값이
     없지만, 그룹 이미지 등 다른 자료 보호 차원에서 비공개를 권장합니다)
   - `kpop_auto` 폴더 전체를 이 저장소에 업로드합니다 (`config.py`는
     `.gitignore` 덕분에 자동으로 제외됩니다)

2. **저장소에 Secrets 등록**
   - 저장소 → **Settings → Secrets and variables → Actions → New repository secret**
   - 아래 항목들을 하나씩 등록합니다 (값은 실제 `config.py`에 넣던 값과 동일):
     - `WP_URL`, `WP_USERNAME`, `WP_APP_PASSWORD`
     - `GEMINI_API_KEY`
     - `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET` (네이버 검색 안 쓰면 생략 가능)
     - `KAKAO_REST_API_KEY` (다음 검색 안 쓰면 생략 가능)

3. **워크플로우 확인**
   - `.github/workflows/auto-publish.yml` 파일이 저장소에 포함되어 있으면,
     깃허브가 자동으로 인식합니다
   - 기본값은 **3시간마다 자동 실행** (`cron: '0 */3 * * *'`, UTC 기준이라
     한국시간으로는 그보다 9시간 뒤입니다)
   - 저장소 → **Actions** 탭에서 "Run workflow" 버튼으로 수동 실행도 가능합니다

### 상태 파일(중복 방지 기록)은 어떻게 유지되나

`posted_links.json`, `posted_titles.json`, `group_images.json` 같은 파일은
매 실행 후 워크플로우가 **자동으로 저장소에 다시 커밋**해서, 다음 실행 때도
이어서 중복 없이 처리됩니다. 로컬 PC에서 돌릴 때와 동일하게 동작한다고
보시면 됩니다.

### 실행 주기 조절

`.github/workflows/auto-publish.yml`의 `cron: '0 */3 * * *'` 부분을 바꾸면
주기를 조절할 수 있습니다 (예: 6시간마다는 `0 */6 * * *`). 너무 자주 돌리면
깃허브 무료 실행 시간 한도(월 2,000분, private 저장소 기준)를 넘을 수 있으니
참고하세요.

### 다른 스크립트도 깃허브 액션으로 돌리고 싶다면

`migrate_from_blogger.py`, `regenerate_images.py` 등도 같은 방식으로
워크플로우를 추가할 수 있습니다. 다만 이런 스크립트들은 보통 "한 번에 몰아서
처리하고 끝"이라, 반복 스케줄보다는 `workflow_dispatch`(수동 실행 버튼)만
있는 워크플로우로 만드는 게 더 알맞습니다. 필요하시면 만들어드릴게요.
